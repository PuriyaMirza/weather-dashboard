## High — verified visually

### The default desktop layout leaves a 2x2 hole

Six default modules — 2 small, `hourly-temperature` large, 2 small, `daily-forecast` large — span 12
cells of the 4-column grid. `grid-auto-flow` is not `dense`, so the trailing large card cannot
backfill the gap beside it: a visibly empty 2x2 box sits under the chart, right of Daily Forecast,
on **every desktop load**, in both themes and both conditions.

- `components/dashboard/card-grid.tsx:160` — the grid className, no `dense`
- `lib/weather/card-layout.ts:24-26` — the size-to-span map

This is a larger version of the already-known "few modules enabled" empty-cell case, which the agent
also reproduced on phone with a single small module. The difference worth noting: that one needed an
unusual configuration, and this one is the **shipped default**.

> Independently re-derived by the main session before this was written down. Walking the placement
> confirms it: rows 1-2 fill as smalls in columns 1-2 and `hourly-temperature` in columns 3-4, which
> leaves `daily-forecast` no 2x2 opening until rows 3-4 columns 1-2 — stranding rows 3-4,
> columns 3-4.

## Medium — verified visually

### The hourly series is printed twice

The hero's hourly strip and the `Hourly Temperature` module restate the same 8-hour series — same
hours, same temperatures — one scroll-length apart, a line chart directly beneath the row strip that
already said it.

The *current-temperature* duplication was fixed correctly in PR #25 (`components/dashboard/hero.tsx`
carries the reading, `temperature` dropped from `DEFAULT_CARD_LAYOUT`). This second overlap was not
addressed, and the agent judges it the more noticeable of the two at phone width, where both land
near-simultaneously.

### Today's high and low appear nowhere by default

The hero shows only the current temperature. The `Temperature` module carries high/low but is off by
default. `Daily Forecast`'s first row *is* today, but it reads "Sat" — unlabelled and styled
identically to every other row (`components/weather/daily-forecast-card.tsx:44-47`) — so connecting
it to "today" requires the reader to already know the weekday.

### The menu buries its frequently-used controls

21 visually identical toggle rows (12 Readings, 9 Panels) precede Arrange, Presets, Units and Theme,
which costs several screens of scrolling on a phone.

- `components/dashboard/menu.tsx:136-172` — the toggle lists
- `components/dashboard/menu.tsx:174-269` — the controls behind them

## Not a finding

A dark circular "N" badge overlaps cards in every phone and desktop capture. This is Next.js's
dev-mode indicator — fixed-position, only present under `next dev` — not app UI. It will not appear
against `next start`.

## Checked and found fine

Arrange mode matches its recent rework exactly: tap-to-lift shows "PLACE HERE" on every other module
with dashed destination outlines, the sticky toolbar swaps Done for Cancel, and press-and-hold drag
still works alongside it. The agent was told to treat the written record as possibly stale and to
report any stale description as a finding — it found none; PRD and ROADMAP are accurate here.

Monochrome, zero radius, hairline rules, Instrument Serif, keyboard parity and severity-words-not-
colour all held in every capture.
